# Split65 0.5.0 Candidate — English release notes

English | [中文](v0.5.0-candidate.zh.md)

## Summary

0.5.0 updates keyboard firmware, the Windows native driver and Companion. It addresses input starvation under continuous RGB replies, discarded independent intensity and a wired ownership race.

## Usage

Close old controllers, flash the supplied 0.5.0 BIN onto the left half, then run the new Companion and click Enable lighting. The existing right-half 0.4.9 firmware remains wire-compatible (split protocol 0x44); flashing both is optional. Do not flash the receiver. The same EXE updates the old bridge driver when its readiness version differs.

## Changes

Keyboard states now have a priority lane with frozen keyboard/overflow pairs and auxiliary fairness. Failed RGB traffic yields to new input. Mode/ownership cleanup precedes USB enabling so a host takeover during startup survives. Both wired output and wireless RGB snapshots now apply the advertised 255-level intensity gain. Wireless scheduling changes from 200 to 100 ms with at most two packets in flight; actual throughput is not guaranteed. Older left firmware is rejected for wireless streaming to prevent the known starvation condition.

## Validation scope

Software regressions, native SDK/WDK and managed net48 compilation, and linked firmware checks passed. New real-hardware input latency, gradient behavior, driver installation and wired control still require validation; this is a candidate, not a claim of completed hardware certification. Chroma layout repair remains included and requires importing/selecting its generated copy.

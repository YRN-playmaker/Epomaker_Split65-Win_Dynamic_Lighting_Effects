# 当前结果与使用限制

更新：2026-10-18。固件保持 v0.4.7，左右使用同一 BIN。

## 用户已确认的结果

- 两半均刷入 v0.4.7 后，移除 OpenRGB 后台，Windows 动态照明能正确识别 Split65，基本亮灭可用。
- 用户报告内置灯效切换可用。此前右半区休眠恢复修复已有确认；两半更新后的长时间休眠回归尚未再次单独确认。
- 用户的 Windows PowerShell 5.1 / WinRT 映射结果中，Split65 的 68 灯位置与源码一致，核对的按键绑定正确，元数据读取无错误。
- 将 Chroma 中的原生及 WDL 鼠标布局移离键盘后，用户确认固定键位串到 Cobra Pro 鼠标的现象消失。

这些是用户实机反馈，开发检查机没有连接该套硬件。不能将其扩展为所有硬件修订、所有效果或长期运行通过。

## OpenRGB 与 Windows 识别

用户两次确认结束或移除 OpenRGB 后原生识别恢复。仅关闭其界面可能仍有后台访问。使用 Windows 动态照明前完全退出 OpenRGB 及相关自动启动进程，避免多个灯控器同时访问设备。后台并发与初始化失败有关，但尚未取得足以归因到某个错误响应的完整 USB 数据。

## Chroma 跨设备串灯

双方同为 v0.4.7 没有解决串灯。用户导出的键盘单键与鼠标效果目标也各自正确，不能归因为选错设备或右侧版本较旧。

导出中的逻辑灯位重叠模型准确对应 P 键及另一布局中的五个冲突键；单独移动鼠标布局后串灯消失。当前可用处理为分离 Chroma 设备布局，详见 [操作和证据范围](CHROMA.md)。没有因此修改固件灯号、按键绑定、USB 身份或硬件几何坐标。

鼠标的原生与 WDL 表示可能同时留在 Chroma 场景中。关闭 Windows 某个设备卡片不能当作已从 Chroma 场景删除该设备的证据。没有 Chroma 内部源码或厂商确认，暂不将坐标模型称为已获官方确认的内部根因。

## 尚有限制

- LampArray 目前仅走 USB 有线模式；2.4G 接收器和蓝牙动态照明未实现。
- 342D:E4C7 是临时实验 PID，没有声称获得厂商正式分配。VIA/EPOMAKER Hub 的旧设备过滤可能不匹配，网页改键改灯未完整验证。
- 使用共享非 Boot HID 接口，BIOS/UEFI 输入未保证。
- InputBinding 固定为出厂 Windows 基础层，VIA 改键不会自动改变灯光按键映射。
- 亮度上限保持 150/255；几何坐标是键盘合拢布局近似值，不会自动获知两半在桌面上的距离和角度。
- 所有灯位逐色、长时间连续输入、无线模式切换、不同 USB 端口/主机和 Chroma 效果的完整回归未完成。
- 未通过微软 HLK 或 Razer 认证，也不隶属于 EPOMAKER、Microsoft 或 Razer。

## 故障资料

正常使用无需安装开发环境。只读映射工具位于 tools/chroma-mapping/Run-Mapping-Check.cmd；报告 TXT 和日期 ZIP 保存在 CMD 同目录，无需管理员。它不改颜色、设备使能、驱动或固件。深度诊断及原始 Feature 检查仅供故障调查，不要与 Windows 初始化并行反复运行。公开反馈前请移除设备序列号等个人信息。
